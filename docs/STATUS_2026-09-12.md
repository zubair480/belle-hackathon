## What the API lane delivers

- 25 routes as thin adapters over dependency-injected handlers: catalog and manual directory
  entry, entity context with sourcing, issues (create, list, detail, patch, comments, causes,
  fixes, verifications, transitions, similar resolutions, export), insights, three optional AI
  routes, bounded read-only agent tools, and the assembly trace routes.
- Enforced rules: idempotent creates, `expectedVersion` stale rejection, closure only after a
  passed verification for the applied fix, failed verification keeps the issue open, reopen
  preserves history, reused fixes become new proposals with the source untouched.
- Attribution: reporting, assigned and confirmed-cause teams are separate; linked suppliers never
  enter confirmed counts; supplier rates are null (N/A) without a complete inspection cohort.
- Explicit wiring: the in-memory double answers only with `RECALL_SERVICES=double`; graph mode
  expects Codey's `graphServices` and fails with `BACKEND_UNAVAILABLE` otherwise. AI is one
  replaceable provider (`none` default, `stub` labeled, `anthropic` needs `RECALL_AI_API_KEY`).
